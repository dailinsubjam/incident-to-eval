# 三种接入方式示例

以下均为虚构的设计演练，无生产数据，也未提供可执行 runner。
选择与实际产品相符的方式，映射到已经核实的接口；不要求照搬名字或字段。

## A. CLI 自主取证，输出 Markdown

假设已有一个通过命令行启动的 Agent，接收事故触发 JSON，使用两个现有只读工具：
一个发现服务/依赖，一个查询指标。最终报告写入本次指定文件，进度写 stderr。

| 项目 | 本题约定 |
|---|---|
| 任务 | 调查 checkout-api 的超时范围，给出证据支持的异常边界和条件处置 |
| 启动 | 只传原始超时告警、调查窗与任务；不预传事后认定的慢依赖对象 |
| 证据 | 服务发现、事故与正常对照的原生一分钟指标；保留非故障对象 |
| 适配 | 将现有工具的 provider 指向版本固定的快照；保持参数、单位、分页与错误合同 |
| 输出 | 本次运行完成后生成的 report.md 全文；stderr、临时文件和旧报告不计分 |
| 验收 | 服务发现可查、指标可关联；实际进程使用回放 provider，最终报告归属本次 run |

若只有指标文件而没有可执行 provider，应交付已冻结证据和待接入项；
不能把慢依赖结论直接塞进触发输入，或声称已测到自主取证。
若接口独立验收通过但 Agent 没查服务发现，应保留能力失败，不删除依赖定位要求。

## B. API 返回 JSON，应用预采集证据

假设产品接收工单，由应用 collector 先抓证据再交给模型。调用结果本身就是交付给消费者的
JSON，不存在页面。假设已核实其响应具有以下字段：

```json
{
  "run_id": "sample-run-7",
  "status": "completed",
  "result": {
    "diagnosis": "调用链的等待主要集中在 inventory 依赖边界，现有数据不能区分服务端与网络。",
    "actions": [
      {"when": "确认依赖仍在超时且下游容量允许", "action": "按现有流程限制重试放大"}
    ],
    "uncertainties": ["缺少依赖服务端观测"]
  },
  "debug": {"candidate_notes": "仅供排查，不属于正式答案"}
}
```

在实验前确定：status=completed 时，选择本次 run_id 对应的 result 原生对象评分；
diagnosis/actions/uncertainties 均在合同内，debug 不在其中。JSON 无需改成文本或页面。
每项评分引用字段路径与实际值，保留原响应和评分输入 hash。

输入绑定是工单到 collector 的实际映射；证据适配位于 collector 的来源接口；
需检查哪些冻结记录进入模型。该实验覆盖应用采集与模型研判，不能称模型自主选择工具。
若只有模型函数调用成功，应报告模块范围，不能声称已验收工单入口和异步完成链路。

## C. 固定证据包的聊天问答

假设用户明确只测已有证据的解释，允许把中性脱敏证据包一次性交给聊天 Agent。
此时按固定输入合同交付证据即可，不需要为了评测而发明查询适配层。
私有评分参考仍隔离，最后一次约定提交是答卷；不得据此评价工具选择、数据发现或分页能力。

同一份材料若以后改为自主调查题，应建立新的接入与任务版本，让 Agent 通过实际接口获取；
不能直接沿用固定输入题的分数宣称自主取证改善。

## 时间与覆盖的小例子

设归档窗口为 [10:00, 10:10)，全部时间同为 UTC，信息截止点为 10:10。
一条事件发生于 10:08，但平台于 10:12 才能查询它；严格历史题应排除，
即使当前已经补采到了该事件。若首次可查询时间未知，只能标记未知或回顾性重建。

Agent 请求 [09:55, 10:05)，快照只有 [10:00, 10:10)。适配器保留原请求，
返回 [10:00, 10:05) 的已有数据并标明前五分钟无覆盖，不能声称全窗无异常。
若原生数据只有完整五分钟计数，查询 [10:01, 10:02) 不支持精确值，
不能按比例拆算，也不能返回零行来假装没有事件。

这些规则分别约束可见性、覆盖和分辨率；不能用一个“数据为空”状态替代。
