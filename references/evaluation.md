# 评分、校准与比较

在拟定检查点、判分或比较实验时使用。优先采用目标项目可执行的规则与框架；
本页不规定特定 Judge、评分比例、文件格式或固定运行次数。

## 从业务判断推导检查点

Diagnosis（诊断）与 Mitigation（应急建议）可以分别报告；只测诊断时不强行补齐处置维度。
每项记录主体、对象、关系、范围与确定性，支持/反证、最低满足、等价答案、遗漏与错误边界、
权重及复核状态。严重错误单列，不能靠其他高分抵消。

- 诊断：定位有价值的对象或异常边界；解释证据支持的机制；说明会影响处置的真实歧义。
  对象定位可以有部分分，但提到名字不自动得到机制分，并列两个现象不等于解释因果。
- 建议：谁对什么采取何种条件行动、为何适用、如何限制风险、怎样确认效果。
  接受有依据的替代方案；实际执行过的历史动作不是唯一标准答案。
- Unknown：检查点若要求解释不确定性，应具体指出未区分的机制或缺证；泛称“需要更多信息”
  不能替代已有证据支持的判断。候选推断也不能被 Judge 擅自加码为唯一根因确证。

只评建议时不要求已经执行，提出恢复标准不要求系统已经恢复；若要判已恢复，
按任务定义检查持续业务结果与必要系统信号，不能单靠告警消失或一次成功。
风险点针对实际动作设计，不要求每个动作都有虚构的可逆回滚。

不把人工工具名、SQL 或调查顺序自动列为必答；其他可靠证据路径支持同一判断应接受。
若专门评价工具选择或操作流程，另声明行为目标。复合项写清必须表达的关系，
能独立指导判断的部分进展宜分开；项数、权重和分母在比较前固定。
“不得误报”与“必须主动说明”不同，不在判分时临时加要求。

## 证据与标准的关系

核心检查点应有题目声明范围内的证据支持，但当前 Agent 尚未使用它不影响该点成立。
本来不可见或仅后验可知的材料只作背景；不能奖励猜中这种答案。
本应可见但漏冻/未接通属于准备度缺口，不能为取得高分降为可选项。
人工确认提高来源可信度，不自动提高事故时可诊断的层级。

## 选择并校准评分器

确定性条件可以用程序判定；语义判断可用人工、LLM 或组合。程序解析成功不证明语义正确，
LLM 给出真实引文也不证明引文支持该判断。为每项保留判定、答卷位置/引用和理由；
结构化答案用字段路径，遗漏无对应引文时直接说明，不编造引用。

首个已授权的真实答卷，先交独立审阅者按同一标准复核，再对照机器原判。
若复核者已看到原分，标明非盲；独立 Agent 意见只是参考，不自动成为人工金标准。
人工标签绑定答卷 hash、输出选择规则、检查点版本和实际确认范围，不把整份标签自动升级。

用来自实际分歧的正反对照校准：同义表达、否定、并列现象与因果、候选与确证、
条件建议与已执行。标准未覆盖但可能正确的答案留复核入口，不能任意奖励或判错。
保留机器原判与人工意见；判断相同但理由不符合标准也应记录风险。
一份答卷重复判多次只测重复稳定性，不是多份独立准确率样本。

## 运行政策与可比性

在运行前记录模型/代码/配置、快照与适配器、正式输出合同、评分标准、Judge 配置、
预算、实际轮数、随机性控制能力、聚合方式和重试规则。每次清理前次答案/记忆污染；
若保留跨轮状态是任务设计的一部分，显式记录，不能称独立重复。

保留每轮结果。合法低分不触发重试；基础设施或 Judge 失败按预声明的有限重试处理，
同时保存失败尝试与分母，不能用高分替换后隐藏原失败。
最低分、均值和全通过比例回答不同问题；若用三次取最低分，明确这是工程聚合策略。
pass^k 关注同一任务 k 次全部成功，pass@k 关注至少一次成功，不把连续分数最低值命名为 pass^k。
少量重复运行不足以证明长期可靠性。

| 要回答的问题 | 最小对照 |
|---|---|
| Agent 改动是否有效 | 固定证据/接口、输出合同、规则与 Judge，改变明确的受测因素 |
| 新证据是否有用 | 固定 Agent 与 Judge，比较明确的有/无证据条件并核对实际访问 |
| Judge 是否改善 | 对同一份保存答卷重评，保留旧判，不额外重跑 Agent |
| 标准修订产生什么影响 | 对固定答卷使用不同规则，分别记录；不能称 Agent 能力变化 |

不同实验条件下的原分可以展示，但不能拼成净能力趋势。字段缺失写未记录，不假定一致。
报告区分题目/环境准备度、有效质量分、严重错误、基础设施失败和实际覆盖。
需要验证泛化时保留未参与调优的案例，按事故或关联事件分组避免相邻窗口泄漏；
反复调优的题可以防回归，不能单独证明广泛 RCA 能力。
